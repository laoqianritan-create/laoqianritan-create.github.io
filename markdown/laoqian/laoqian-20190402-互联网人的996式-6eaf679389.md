# 互联网人的996式“薪酸”

以上代码纯属胡诌，程序员GG别挑Bug哈～

我知道读者群体中有相当比例的程序员，所以忍不住写写这个话题。

早上起来还专门给三个程序员朋友打了电话，大家一开始的态度都是嘴上很反对，聊着聊着，又有些身体很诚实的无奈。

996是一场从市场到公司管理层到业务到开发端的压力传导。

很多时候996不是明文规定，而是给你的活儿加班都不一定做得完。

程序员的工作，两种状态兼而有之：

一种是成熟业务，编程相对机械，基本靠累时间累代码完成；

一种是新业务，编程需要思考。

特别希望能有三四个小时的高效专注时间—但很多时候这种状态比休息时间还要奢侈，上班期间开会，扯皮，微信钉钉一会儿一响...

反倒是下班之后，人少又安静的晚上，成了最适合工作的时间。

一个程序员说他效率最高的时候就是接私活，只能利用空闲时间，赶快搞完赶紧结款。

这种现象到底是「公司管理问题」还是「个人问题」，很难界定。

相比较而言，「十十六」要好于「九九六」，起码早上可以多睡会儿，这真的非常重要。

最闹心的996，是为毫无希望瞎JB搞的新业务加班。

程序员也不傻，产品经理写个需求文档都要解释好项目意义，大家都是职场人，如果对项目没有认同感，没有正向反馈。

长时间为沙雕业务做着无效开发，真是分分钟想离职。

一个程序员的吐槽让我印象深刻，他说：

> 其实加班一段时间，会觉得还挺充实。但当996成为日常，时间久了，身心都特别不爽！

程序员是青春饭，很大原因就是因为长期加班消磨热情，消耗身体。

另一个侧面是，整个互联网行业也挺青春饭，前期收割。

绝大部分程序员都面临着一个焦虑：35岁之后，我怎么办？

当然，其他行业又何尝不是如此。

年轻时累一些，拼一些，合理且必要。

只是，这种状态是否需要996这样的制度来约束，值得探讨。
